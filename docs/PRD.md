# 设备云监 PRD v1

> 版本：第 2 周 v1 · 汇总自访谈清单 / 用户故事 / 验收标准 / 用例图  
> 仓库：https://github.com/999-ASD/device-cloud  
> 约束：字段与端口对齐课程 `01`；纯软件模拟，单机运行。

## 1. 背景与目标

工业现场需要对设备运行状态做秒级感知，并在异常时形成「监控 → 报警 → 工单 → 报表」闭环。本课程项目「设备云监」以 **一台 Modbus TCP 模拟从站（端口 5020）** 为数据源，在 Windows 本机用全开源技术栈完成：

1. 采集遥测并入库；  
2. 监控页实时展示；  
3. 超限报警与确认；  
4. 报修/巡检工单闭环；  
5. （P1）备件与统计报表。

**目标一句话**：用可复现的软件模拟，把工业运维主链路跑通，并为后续周次的建模、实现与测试提供需求基线。

## 2. 目标用户与角色

| 角色 | 主要目标 |
|------|----------|
| 设备管理员 | 维护台账与备件，关注整体运行与报警态势 |
| 运维工程师 | 盯监控、处理报警、执行/关闭报修工单 |
| 班组长 | 派发/跟踪工单，查看统计做交接 |

> v1 **单角色可用**（不做登录权限体系）；三角色用于描述职责，不强制 ACL。

## 3. 功能需求

### P0（Must）

| 模块 | 需求摘要 | 主要表/字段 |
|------|----------|-------------|
| 设备台账 | 设备增删改查；编号唯一；支持按 `code` 搜索（见 AC-2） | `device`：code/name/model/location/owner/status |
| 实时监控 | 展示温度/转速/产量/运行状态/安全门；断线提示与重连后继续刷新；温度 ×10 还原后再显示/比较 | `telemetry`：temperature/speed/output_count/run_status；点位 DI10001 |
| 报警管理 | 还原温度 **≥ 60℃** 生成 `level=high`；确认 `acked`；清除 `cleared_at`；短时去重 | `alarm`：type/level/message/ts/acked/cleared_at |
| 巡检/报修工单 | 可由报警创建；指派 `assignee`；处理中→已关闭并写 `closed_at` | `work_order`：type/title/status/assignee/content/created_at/closed_at |
| Modbus 采集 | 轮询模拟从站，供监控与报警使用（用例 include） | 端口 5020；见第 6 节 |

### P1（Should）

| 模块 | 需求摘要 | 主要表 |
|------|----------|--------|
| 备件管理 | 备件主数据与出入库记录 | `spare_part` / `spare_record` |
| 统计报表 | 利用率（基于 run_status）、报警次数、工单关闭情况 | `telemetry` / `alarm` / `work_order` |

### P2（Could / 加分）

| 模块 | 需求摘要 |
|------|----------|
| 智能预警 | 基于趋势的预报警（须仍使用现有表字段，不新增幻觉列） |
| 站内消息 | 仅系统内提示（若做）；**不包含**邮件/短信/微信 |

## 4. 非功能需求

| 类别 | 需求 | 可测指标 |
|------|------|----------|
| 性能 | 采集延迟 | 从站寄存器变化 → 入库/监控可见 **≤ 2 秒** |
| 性能 | 页面刷新 | 监控页自动刷新周期 **≤ 3 秒** |
| 可用性 | 断线自愈 | 断开后自动重连并恢复刷新 **≤ 10 秒** |
| 可靠性 | 采集异常不拖垮进程 | 异常记日志，服务进程不崩溃 |
| 兼容性 | 运行环境 | Windows 10/11 + Python 3.11+ 单机；Node 20+（前端） |
| 可测试性 | 验收可观察 | 关键路径可用 Given/When/Then（见 `acceptance_criteria.md`） |

## 5. 数据需求

引用课程 `01` 约定的 **6 张表**（单数小写），v1 不新增表：

| 表 | 用途 | 关键字段（示例） |
|----|------|------------------|
| `device` | 设备台账 | code/name/model/location/owner/status |
| `telemetry` | 实时/历史遥测 | temperature/speed/output_count/run_status |
| `alarm` | 报警 | type/level/message/ts/acked/cleared_at |
| `work_order` | 工单 | type/title/status/assignee/content/created_at/closed_at |
| `spare_part` | 备件主数据 | （按 01 列名） |
| `spare_record` | 出入库记录 | （按 01 列名） |

**禁止**：`severity_score`、`notify_channel`、`operator_id` 等未在 01 出现的列名。

## 6. Modbus 采集需求

| 点位 | 含义 | 备注 |
|------|------|------|
| HR40001 | 温度 | 按 **×10** 存储，显示/阈值比较前 ÷10 |
| HR40002 | 转速 | |
| HR40003 | 产量 | |
| HR40004 | 运行状态 | |
| DI10001 | 安全门 | |
| 线圈 00001 / 00002 | 启动 / 停止 | 若 v1 仅监控可读，写操作可标为后续 |

- 传输：Modbus TCP，**端口 5020**（非特权 502）  
- 轮询：约 **1–2 秒**  
- 与用例关系：「查看实时监控」「处理报警」**include**「采集 Modbus 数据」

## 7. 界面与交互需求（页面清单）

与 `frontend/src/views` 命名方向一致：

| 页面 | 职责 |
|------|------|
| Dashboard | 实时监控、断线提示、关键量刷新 |
| Devices | 设备台账查询/维护（含按 code 搜索） |
| Alarms | 报警列表、确认、去重后的展示 |
| WorkOrders | 工单创建/派发/关闭 |
| Spares | 备件与出入库（P1） |
| Stats | 简易统计（P1） |

交互要点：搜索 **≤ 3 秒**返回；报警确认改变 `acked`；关单写入 `closed_at`。

## 8. 边界与不做的事（Out of Scope）

**明确不做：**

1. 真实工业现场硬件接入（仅本机模拟从站）  
2. 多租户 / 多工厂云平台  
3. 权限体系、多角色审批（v1 单角色）  
4. 移动 App  

**同期不做（可记 Won't）：** 邮件 / 短信 / 微信等站外通知。

## 9. 验收标准汇总

详见 `docs/acceptance_criteria.md`：

| 编号 | 摘要 |
|------|------|
| AC-1 | 还原温度 ≥ 60℃ → ≤2s 生成 high 报警；acked 默认 false；60s 去重 |
| AC-2 | 按 `device.code` 搜索，≤3s，结果可观察 |
| AC-3 | 报修工单关闭 → `status=已关闭` 且写入 `closed_at` |

更完整用户故事与 MoSCoW 见 `docs/user_stories.md`；用例关系见 `docs/use_case.md`。

### 里程碑（课程节奏，示意）

| 阶段 | 内容 |
|------|------|
| 第 1 周 | 环境与仓库骨架（已完成） |

### 主要风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| AI 幻觉字段进入建模 | 第 5 周前后返工 | 字段一律对表 01；PRD/故事禁止未列字段 |
| 断线丢数或界面显示过期值 | 误判工况 | NFR：≤10s 重连；断线明示 |
| 端口 5020 被占用 | 采集失败 | 自检脚本 + FAQ 释放端口 |
| 温度未 ×10 还原 | 误报/漏报 | AC-1 明确还原后再比阈值 |
