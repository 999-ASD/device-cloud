# ADR-001：后端选用 FastAPI

- 状态：已采纳
- 日期：第 3 周
- 关联：`01_项目设定与工具栈.md` 技术栈；后续采集服务与 REST API

## 背景

设备云监需要本机提供 REST API（设备/遥测/报警/工单等），并与 **异步 Modbus 轮询采集** 长期共存。课程约束为全开源、单机可运行、Windows 为主、Python 3.11+。需要选定一个后端 Web 框架，能同时支撑 HTTP 接口与后台协程任务，并尽量减少样板代码。

## 决策

采用 **FastAPI + Uvicorn** 作为后端与 API 层；请求/响应模型用 **Pydantic** 校验。

## 理由

1. **原生 async**：便于把采集循环放进事件循环，避免「同步框架 + 另起线程」的复杂拆分。  
2. **契约友好**：自动生成 OpenAPI；与本周 `docs/api.md` 的路径/schema 容易对齐，前后端可并行。  
3. **校验强、许可友好**：Pydantic 校验请求体；MIT 许可，符合课程「纯开源免费」要求。

## 代价

1. **生态心智与 Django/Flask 不同**：团队若只熟悉同步视图，需要补 async/await 与依赖注入习惯。  
2. **不自带重量级 Admin/ORM 全家桶**：复杂后台管理、迁移工具链需自选（本课用 SQLite + 轻量访问即可）。  
3. **文档与教程碎片化**：个别第三方库对 async 支持不完整时，要自行确认是否阻塞事件循环。

## 备选方案及未采纳原因

| 备选 | 未采纳原因 |
|------|------------|
| Flask | 默认同步；要做异步采集需额外线程/队列，v1 结构更散，OpenAPI 需插件拼装。 |
| Django | 偏重；课程无多用户权限/Admin 刚需，学习与目录成本高于收益。 |
| 纯 Starlette | 能力够但生态与教学资料不如 FastAPI 完整，开发效率较低。 |
