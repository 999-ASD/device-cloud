# ADR-002：前端选用 Vue 3 + Element Plus

- 状态：已采纳
- 日期：第 3 周
- 关联：监控看板、设备台账、报警/工单页面；本周 `docs/prototype.html` 线框后续落地

## 背景

系统需要浏览器端管理界面：设备台账表格、实时监控数值与断线提示、报警确认、工单流转、（P1）备件与统计。课程要求 Node 20+、组件库成熟、图表可接 ECharts，且全开源。需选定 SPA 框架与 UI 组件方案，保证课内能按时做出可用页面。

## 决策

采用 **Vue 3 + Vite** 构建前端；UI 使用 **Element Plus**；实时/统计图使用 **ECharts**。

## 理由

1. **上手快、课内资料多**：组合式 API 清晰，Vite 热更新适合课堂迭代。  
2. **表格/表单场景匹配**：台账、报警列表、工单状态天然适合 Element Plus 现成组件。  
3. **许可与生态合规**：Vue/Vite/Element Plus/ECharts 均为 MIT 或 Apache-2.0，满足「不引入商业闭源前端」。

## 代价

1. **依赖 Node 工具链**：本机需安装 Node 20+；同学环境不一致时，`npm install` 失败会阻塞联调。  
2. **包体与构建成本**：相对「纯静态 HTML」更大；首屏与依赖体积需在后续注意按需引入。  
3. **状态管理需自律**：若不约定 API 封装与错误态（空/加载/失败），容易每页各写一套，和本周原型三态脱节。

## 备选方案及未采纳原因

| 备选 | 未采纳原因 |
|------|------------|
| React + Ant Design | 同学栈不统一，课程仓库与示例以 Vue 目录约定（`frontend/src/views`）为准。 |
| 仅原生 HTML/CSS/JS | 可做线框（本周 prototype），但完整台账/图表/路由成本高，不利于第 6 周页面交付。 |
| Angular | 概念重、脚手架大，超出本课单机监控系统的复杂度预算。 |
