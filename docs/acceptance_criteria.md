# 验收标准（关键用户故事 · Given/When/Then）

> 对应第 2 周任务二中的 Must 故事；字段名对齐 `01`（alarm / work_order / device）。  
> Then 须可观察、可量化；不含「尽快/大概/良好」等不可测表述。

## AC-1 温度超限报警（Must）

**故事**：温度还原后 ≥ 60℃ 时自动生成 high 级报警并出现在监控页。

- **Given** 设备 `EM-001` 处于可采集状态，且 Modbus TCP（5020）连接正常；温度点位 HR40001 按 ×10 存储，比较前已 ÷10 还原为℃  
- **When** 连续两次采集得到的还原温度 **≥ 60℃**（含恰好等于 60℃）  
- **Then** 系统在 **≤ 2 秒** 内写入一条 `alarm` 记录：`type` 表示温度超限、`level="high"`、`message` 非空、`ts` 为当前时间，且监控页报警列表可见该条  
- **And** 该报警默认 `acked=false`，直到运维在监控页点击「确认」后变为 `acked=true`  
- **And** 同一设备、同一 `type` 在 **60 秒内** 不因持续超限而重复新建报警（去重/抑制）  
- **And** 若还原温度 **&lt; 60℃**，不新建本条 high 级温度报警  

## AC-2 台账按编号搜索（Must）

**故事**：按设备编号搜索台账（对应 device.code）。

- **Given** 台账中已存在 `device.code="EM-001"` 的设备，且另有至少一台 `code` 不同的设备  
- **When** 我在台账搜索框输入 `EM-001` 并确认搜索  
- **Then** 列表在 **≤ 3 秒** 内返回，且仅显示 `code` 精确匹配或按约定规则包含 `EM-001` 的设备行  
- **And** 列表中每行至少展示 `code`、`name`、`status`（与台账页字段一致）  
- **And** 输入不存在的编号时，列表为空或显示「无结果」，不报错退出页面  

## AC-3 报修工单关闭（Must）

**故事**：报修工单处理完成后可关闭。

- **Given** 存在一张 `work_order`，`type` 为报修、`status="处理中"`，且已指定 `assignee`  
- **When** 处理人填写 `content`（处理说明非空）并点击「关闭」  
- **Then** 该工单 `status` 变为 `"已关闭"`，且 `closed_at` 记录为关闭操作时刻（可观察于详情/列表）  
- **And** 关闭成功后，该工单不可再被同一按钮重复关闭（或再次点击给出明确已关闭提示）  
- **And** 不写入课程约定外字段（不使用 `operator_id` 等）  

## 人工审查摘要

| 项 | 处理 |
|----|------|
| AI「尽快/良好/有点高」 | 改为 ≤2s / ≤3s、≥60℃、明确 status 值 |
| AI `operator_id` / 站外通知 | 删除；关单只用 `status`/`closed_at`/`assignee`/`content` |
| 边界 | 明确 ≥60℃ 含等于；报警 60 秒去重；关单触发 `closed_at` |
| 可测试性 | 每条 Then 均可在页面或库表观察 |
