# 设备管理员访谈问题清单（最终版）

> 访谈对象：工厂设备管理员（可旁听运维工程师/班组长）  
> 范围：纯软件模拟 · Modbus TCP 5020 · 六表 device/telemetry/alarm/work_order/spare_part/spare_record  
> 总条数：18（每组 ≤3）

## 1. 设备台账

- 每台设备是否必须具备唯一编号、名称、型号、安装位置？缺一项能否入库？（想拿到：device.code/name/model/location）
- 设备「负责人」在台账里如何填写？是否对应字段 owner？（想拿到：device.owner）
- 设备状态有哪些取值（如运行/停机/维修）？状态变更是否影响继续采集？（想拿到：device.status）

## 2. 实时监控

- 监控页需要同时展示温度、转速、产量、运行状态吗？安全门状态是否一并展示？（想拿到：telemetry.temperature/speed/output_count/run_status；安全门点位 DI10001）
- Modbus 连接断开后，界面如何提示？重连成功后数据从何时继续刷新？（想拿到：断线重连策略，关联 telemetry 刷新时序）
- 温度点位 HR40001 按 ×10 存储时，界面显示与报警阈值比较前是否必须先 ÷10 还原？（想拿到：温度 ×10 还原规则，字段 temperature）

## 3. 报警管理

- 温度阈值多少℃触发报警？级别如何划分？读数明显越界（负数/超物理上限）时丢弃、钳制还是单独报警？（想拿到：alarm.type/level/message/ts；越界处理）
- 运维在监控页「确认」报警后，acked 如何变化？清除完成是否写入 cleared_at？（想拿到：alarm.acked/cleared_at）
- 同一设备同一条件在短时间重复满足时，是生成多条报警还是合并/抑制？（想拿到：报警去重策略；alarm 写入规则）

## 4. 巡检/报修工单

- 报修工单最少需要哪些信息？能否从一条未关闭报警一键生成？（想拿到：work_order.type/title/status/assignee/content/created_at）
- 工单「关闭」的判定条件是什么？关闭后是否必须填写 closed_at？（想拿到：work_order.status/closed_at）
- 关闭后若同类报警条件再次出现，是否允许再自动建单？（想拿到：关单后再生单规则，关联 alarm/work_order）

## 5. 备件管理

- 备件主数据需要登记哪些属性（名称、规格、库存数量等）？（想拿到：spare_part）
- 出入库记录是否要关联工单或设备？一次出入库记哪些字段？（想拿到：spare_record）
- 库存低于多少需要提醒？提醒是否只在本系统内展示即可？（想拿到：spare_part 库存阈值/提醒口径）

## 6. 统计报表

- 设备利用率如何定义？是否按 run_status 为运行的时长占比计算？（想拿到：利用率口径，基于 telemetry.run_status）
- 报警统计按 type/level 汇总时，时间窗口默认日还是周？（想拿到：报警统计口径，表 alarm）
- 工单统计要看哪些状态分布与关闭时长？（想拿到：工单统计口径，表 work_order.status/created_at/closed_at）

## 被裁剪掉的问题及理由

- 「是否需要登录账号/权限才能改台账」→ **删除**：引入权限体系，超出 v1 范围（Won't）。
- 「是否需要手机 App 推送实时曲线」→ **删除**：移动 App，超出范围。
- 「是否需要多级审批和邮件通知」→ **删除**：审批流与站外通知，超出范围。
- 「你们觉得备件模块好用最重要的一点是什么」→ **删除**：主观题，无法落到字段/表。
- 「是否要上云做多工厂对比看板」→ **删除**：多租户/云平台选型，超出范围。
- （补做）原稿未强调「温度 ×10 还原 / 断线重连 / 报警去重 / 越界处理 / 关单条件」→ **人工补入**第 2、3、4 组相关问题。
